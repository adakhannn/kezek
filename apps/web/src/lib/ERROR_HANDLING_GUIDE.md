# Обработка ошибок HTTP

Статус: указатель на действующие правила, обновлён 1 ноября 2026.

Точный контракт helpers и различия существующих ответов описаны в [API_ERROR_FORMATS](API_ERROR_FORMATS.md). Порядок реализации нового обработчика — в [HOWTO_NEW_API_ENDPOINT](HOWTO_NEW_API_ENDPOINT.md). Эти два руководства заменяют прежние дубли примеров.

Ключевые условия:

- `createErrorResponse` требует явного HTTP status для ожидаемого отказа; default — 500.
- Переданные `details` не скрываются в production автоматически.
- `withErrorHandler` ловит исключения, но не проверяет бизнес-успех возвращённого ответа.
- Ожидаемые ошибки передавать явным результатом, а не рассчитывать на распознавание текста exception.
- Изменение envelope согласовывать с потребителями; текущий API не полностью унифицирован.

Источники: [apiErrorHandler.ts](apiErrorHandler.ts), [API guide](../../../../API_DOCUMENTATION.md). Проверки выбираются по [CONTRIBUTING](../../../../CONTRIBUTING.md).
