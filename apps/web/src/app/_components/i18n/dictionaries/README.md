# Структура модульных словарей

Этот каталог содержит словари, разбитые по доменам для лучшей организации и поддержки.

## Новый текст интерфейса

Весь видимый текст идёт через `t('группа.экран.имя', 'Русский текст')`, а ключ добавляется сразу в ru, ky и en той группы, где он используется (`pnpm check:i18n` проверяет паритет). Русский текст `.tsx` и `.ts` вне `t()` считается по файлам и сверяется с [базой](../../../../../../../scripts/i18n-untranslated-baseline.json) (FE-10): новый текст без перевода роняет проверку, а после перевода базу нужно обновить через `node scripts/check-i18n.mjs --write-baseline`. Модуль `.ts` без доступа к `useLanguage()` получает `t` параметром или возвращает ключ, который переводит вызывающий компонент. Админка переведена (группы `admin`, `adminOps`, `adminAnalytics`, `adminAccess`, `adminCatalog`), а тексты юридических страниц лежат в `legal.ru/ky/en.ts`: их читает только серверный [`legal.ts`](../legal.ts), в клиентский бандл они не входят. В базе сознательно остаются письмо с временным паролем и ответы ботов (у получателя нет сохранённого языка или канал его не учитывает), ответы только для мобильного приложения, внутренние ошибки и сравнение текста.

## Сообщения API

Сервисы отвечают по-русски, а [`serverMessages.ts`](../../../../lib/serverMessages.ts) переводит ответ на язык cookie `kezek_lang`, а без неё — заголовка `X-Kezek-Locale` (его отправляет мобильное приложение): поля `message` и `error` JSON-ответа и `message` каждой ошибки валидации в `details.errors`. Перевод делают `withErrorHandler` и `withRateLimit`, а маршруты без них оборачиваются в `withLocalizedMessages`. Словари — `server<Группа>.ru/ky/en.ts` (`serverCommon`, `serverAuth`, `serverBooking`, `serverStaff`, `serverBusiness`, `serverAdmin`). Их импортирует только `serverMessages.ts`, в клиентскую сборку они не попадают. Значение ru — точный русский текст ответа или шаблон с `{параметром}` на месте подставленного значения (имени, числа, даты); перевод содержит те же параметры. Параметр подставляет только значение, а не русское слово, поэтому сообщение из русских кусков собирается одним шаблоном. Новое русское сообщение API добавляется в словарь своей группы сразу на трёх языках, иначе `pnpm check:i18n` его не пропустит. [Тест](../../../../__tests__/lib/serverMessages.test.ts) проверяет, что каждое сообщение словаря переводится. Мобильное приложение передаёт свой язык заголовком `X-Kezek-Locale` и сохраняет его в профиль через `POST /api/profile/locale` с Bearer-токеном; его словари описаны в [apps/mobile/src/i18n/README.md](../../../../../../mobile/src/i18n/README.md).

## Уведомления о бронировании

`serverNotifications.ru/ky/en.ts` — тексты писем, Telegram и WhatsApp о бронировании, письма о закрытии смены и уведомлений о заявках на роль и приглашениях (FE-10). Их импортирует только [`notificationText.ts`](../../../../lib/notifications/notificationText.ts); язык берётся из `profiles.preferred_locale` получателя, а не из cookie запроса. Значение ru — прежний русский текст сообщения, его нельзя менять без обновления тестов уведомлений. Сообщения API из этой группы не переводятся.

## Структура

Каждый домен имеет три файла для трех языков:
- `{domain}.ky.ts` - киргизский язык
- `{domain}.ru.ts` - русский язык  
- `{domain}.en.ts` - английский язык

## Домены

### Основные домены:
- `auth.*` - авторизация и вход
- `booking.*` - публичный поток бронирования
- `home.*` - главная страница
- `header.*` - шапка сайта
- `footer.*` - подвал сайта

### Дашборд и управление:
- `dashboard.*` - дашборд владельца бизнеса
- `staff.*` - управление сотрудниками
- `services.*` - управление услугами
- `branches.*` - управление филиалами
- `finance.*` - финансовая статистика

### Административная панель:
- `admin.*` - административная панель (можно разбить на подмодули: admin/users, admin/categories, admin/businesses и т.д.)

### Общие:
- `common.*` - общие ключи (loading, noData, ok, error и т.д.)
- `datePicker.*` - компоненты выбора даты
- `bookings.*` - управление бронированиями
- `cabinet.*` - личный кабинет клиента
- `review.*` - отзывы
- `map.*` - карты
- `profile.*` - профиль пользователя
- `staffCabinet.*` - кабинет сотрудника
- `staffFinance.*` - финансы сотрудника

## Паттерн создания модуля

```typescript
// auth.ky.ts
export const authKy = {
    'auth.title': 'Kezek',
    'auth.subtitle': '...',
    // ... остальные ключи
} as const;
```

## Сборка словарей

Все модули собираются в `index.ts` с помощью функции `mergeDictionaries()`:

```typescript
export const ky: Translations = mergeDictionaries(
    authKy,
    bookingKy,
    dashboardKy,
    // ... остальные модули
);
```

## Миграция

1. Создать модули для домена (ky, ru, en)
2. Добавить импорты в `dictionaries/index.ts`
3. Добавить модули в `mergeDictionaries()` для каждого языка
4. После миграции всех доменов обновить `LanguageProvider.tsx` для использования модулей
