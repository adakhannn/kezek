# Отладка мобильного приложения

Статус: справочник, обновлён 1 ноября 2026. Для отдельной разрешённой dev-сессии; диагностика продукта этой редакцией не запускалась.

Начните с [классификации симптома](TROUBLESHOOTING.md). Репозиторий использует Expo 54 и React Native 0.81 по [package.json](package.json); интерфейс инструмента зависит от клиента и SDK.

## JavaScript и интерфейс

Для приложения с Hermes используйте React Native DevTools: Developer menu → Open DevTools. В актуальном руководстве Expo этот инструмент заменяет прежний Remote JS Debugging; точное наличие пунктов сверять для установленного клиента. Dev menu можно вызвать клавишей M в терминале работающего Expo CLI для подключённого устройства/эмулятора. [Официальные инструменты Expo](https://docs.expo.dev/debugging/tools/).

В DevTools искать первый stack frame приложения, состояние компонента и конкретный неуспешный запрос. Один console log не подтверждает успешную запись в БД. Нативный crash требует нативных логов Android/iOS, а не только JavaScript console.

## Безопасный диагностический результат

- Зафиксировать выбранный экран/действие, ожидаемый результат и время.
- Сохранить ошибку и относящиеся к ней строки исходников.
- Для сети сохранить method/path/status; значения Authorization, cookies, OTP, auth code и тела с персональными данными исключить.
- Для env проверить имя/наличие/среду через [справочник](../../ENV_GUIDE.md); не выводить всю конфигурацию.
- Изменять по одному установленному условию и проверять тот же симптом.

Глобальный React Native Debugger, новый пакет или ослабление сетевой защиты не являются обязательными шагами проекта. Если доступный метод не даёт нужного наблюдения, записать ограничение вместо обхода доступа. Результаты проверки оформляются по [TESTING_GUIDE](../../TESTING_GUIDE.md).
