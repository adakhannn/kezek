# Smoke-сценарии mobile

Статус: сценарии для планирования проверки, обновлены 1 ноября 2026. Все пункты ниже — условия наблюдения, а не выполненные PASS.

Команды и границы Jest: [TESTING.md](TESTING.md). Перед проверкой на устройстве выбрать разрешённый стенд, роль, данные и допустимые побочные эффекты. Финансовые записи, отправка OTP и новые fixtures не возникают из самого чек-листа.

| Сценарий | Ожидаемое наблюдение | Что сохранить |
| --- | --- | --- |
| Запуск | Выбранный клиент загружает приложение с согласованной конфигурацией | SDK/client/platform, результат загрузки и первая ошибка |
| Вход и восстановление | Конкретный разрешённый способ входа возвращает ожидаемую identity | Способ входа, этап, результат без tokens/OTP; отдельно известный риск ENG-01 |
| Переходы записи | Выбранные филиал, услуги, сотрудник и дата сохраняются между шагами; ошибка загрузки видима | Входные условия и ожидаемые доступные слоты; отправку записи проверять отдельно |
| Кабинет клиента | Отображаются ожидаемые записи выбранного пользователя | Независимый ожидаемый набор; пустой список без данных не является проверкой полноты |
| Рабочее место сотрудника | Ожидаемая смена и позиции доступны нужной роли | Дата/статус/ожидаемые суммы; изменение денег требует отдельного сценария |
| Сеть/возврат в приложение | Ошибка и повтор не создают лишнюю запись или чужой контекст | Исходное состояние, действие и результат после возврата |

Для iOS и Android указывать реальные platform/OS/client отдельно. Результат симулятора не записывать как результат физического устройства. Список не покрывает все требования mobile и не устанавливает разрешение выпуска.

Сохранённые регистры читать по конкретному вопросу: [mobile catalog](../../docs/MOBILE_TESTING_AREAS_CATALOG.md), [mobile bugs](../../docs/MOBILE_BUG_REGISTRY.md).
