# Диагностика мобильного приложения

Статус: действующий справочник, редакция 1 ноября 2026. Команды и пути сверены с репозиторием; запуск на устройстве в этой задаче не выполнялся.

Подготовка среды: [GETTING_STARTED](../../GETTING_STARTED.md). Конфигурация: [ENV_GUIDE](../../ENV_GUIDE.md#mobile). Сначала установить, на каком слое возникла ошибка; сообщение «Something went wrong» само по себе причины не определяет.

## Разделить причины

| Симптом | Что установить | Следующий шаг |
| --- | --- | --- |
| Не загружается приложение/remote update | Выбранный клиент, SDK из [package.json](package.json), доступность dev-сервера с устройства | Проверить сеть и совместимость клиента; это ещё не ошибка API Kezek |
| Приложение открылось, данные не загружаются | Метод/path API, HTTP status или сетевой отказ, выбранный dev API | Проверить [apiUrl resolver](src/lib/apiUrl.ts); localhost на телефоне означает телефон |
| Supabase settings отсутствуют | Путь локальной конфигурации и наличие нужных имён | Сверить [supabase.ts](src/lib/supabase.ts) и ENV_GUIDE, не печатая значения |
| Не восстанавливается вход | Способ входа, этап callback/exchange, версия приложения | Читать выбранную auth-цепочку и ENG-01/08 в [реестре](../../docs/ENGINEERING_FINDINGS.md); повторный вход не доказывает исправление |
| Ошибка импорта/сборки | Первый stack frame проекта, версия Node/pnpm, соответствие lockfile | Сверить общую установку; массовое удаление зависимостей не является диагнозом |

## Сеть и dev-сервер

После подготовки разрешённого стенда команда из корня — `pnpm -C apps/mobile start`. Сначала проверить, что устройство видит выбранный сервер. Для LAN компьютер и телефон должны иметь доступ друг к другу. Tunnel может помочь при ограничениях локальной сети, но использует внешнее соединение и обычно медленнее; его выбирают осознанно для dev-сессии. [Expo: подключение устройства](https://docs.expo.dev/get-started/start-developing/).

При установленной причине, связанной с bundler cache, для своего остановленного dev-сервера доступно `pnpm -C apps/mobile exec expo start --clear`. Очистка кэша не меняет неверный API URL, ACL, схему БД или недоступный backend. Не завершать неизвестный процесс по PID из старого отчёта.

`expo-dev-client` уже указан в package.json. Добавление новой зависимости, обновление SDK или нативная сборка — отдельное изменение проекта, требующее проверки совместимости. Слово «последняя версия Expo Go» не заменяет соответствие SDK проекта и клиента.

## Что приложить к диагностике

Версию исходников и приложения, платформу/ОС, выбранный тип клиента, шаг воспроизведения, время, ожидаемый результат, фактическое сообщение и безопасный фрагмент stack trace. Для API — метод/path и статус без tokens/cookies/телефонов. Сохранить первую причину, а не только последующий общий экран ошибки.

[Инструменты отладки](HOW_TO_DEBUG.md), [Expo account](EXPO_LOGIN.md), [проверки mobile](TESTING.md). Production URL, реальные аккаунты и повторные финансовые операции не используются как диагностические значения по умолчанию.
