# GLOSSARY.md — глоссарий ключевых терминов Kezek

Единый словарь терминов для онбординга и согласованной терминологии в коде, UI и документации.

## Бизнес и сущности

- **Бизнес (business)**: юридическое или фактическое лицо (салон, студия), владелец которого управляет филиалами, услугами, сотрудниками и промоакциями.
- **Филиал (branch)**: физическая точка обслуживания (адрес + координаты), привязанная к конкретному бизнесу. У филиала есть расписание, услуги и сотрудники.
- **Сотрудник (staff)**: мастер или администратор, работающий в филиале. Сущность `staff` привязана к `profiles.user_id`.
- **Клиент (client / profile)**: пользователь, который делает бронирования и может иметь личный кабинет. В БД представлен через таблицу `profiles` и связанные `bookings`.

## Кабинеты и роли

- **Роль (role)**: тип доступа пользователя в системе:
  - **Владелец (owner)**: владелец бизнеса, имеет полный доступ к управлению бизнесом.
  - **Администратор (admin/manager)**: управляет филиалами, сотрудниками, расписанием, промо.
  - **Сотрудник (staff)**: видит свои смены, записи, финансовую информацию.
  - **Клиент (client)**: видит свои бронирования и историю.
- **Кабинет (cabinet)**: UI‑область под конкретную роль:
  - **Кабинет владельца / админа**: дашборд, управление бизнесом, филиалами, услугами, промо, аналитика.
  - **Кабинет сотрудника (staff cabinet)**: расписание, смены, записи, финансовая статистика.
  - **Кабинет клиента**: история и управление своими бронированиями.
- **Выбор кабинета / бизнеса**: сценарий, когда пользователь с несколькими ролями/бизнесами выбирает, под каким контекстом работать (страница `/select-cabinet`).

## Бронирования и расписание

- **Бронь / бронирование (booking)**: запись клиента на услугу в определённый филиал, к конкретному сотруднику и на определённое время. Основная сущность — таблица `bookings`.
- **Комплекс услуг (service complex)**: несколько услуг, выбранных клиентом на один визит к одному мастеру в один временной слот; длительность визита равна сумме длительностей услуг. Состав хранится в таблице `booking_services`. См. [Комплексы услуг](SERVICE_COMPLEXES_FEATURE.md).
- **Состав бронирования (booking composition)**: перечень услуг одного бронирования (визита). Для брони с одной услугой совпадает с основной услугой (`bookings.service_id`); для комплекса услуг — список строк в `booking_services` с порядком и длительностями.
- **Слот (slot)**: потенциальное время для записи (начало/конец, мастер, филиал), формируется функцией `get_free_slots_service_day_v2` (или `get_free_slots_complex_day_v1` для комплекса услуг) и пост‑обрабатывается в доменном модуле расписаний.
- **Расписание (schedule)**: совокупность правил и доступных слотов для сотрудников и филиалов (включая временные переводы мастеров).
- **Статус брони (booking status)**:
  - `hold` — бронь в удержании (резерв),
  - `confirmed` — подтверждённая бронь,
  - `paid` — оплаченное посещение,
  - `cancelled` — отменённая бронь,
  - `no_show` — клиент не пришёл.

## Смены и финансы

- **Смена (shift)**: рабочий период сотрудника (обычно день), в течение которого он принимает клиентов. Представлена таблицей `staff_shifts`.
- **Позиция смены (shift item)**: отдельный клиент/услуга/сумма внутри смены (`staff_shift_items`).
- **Гарантия (guarantee)**: минимальная сумма выплаты сотруднику за смену, даже если клиентов было мало (фикс или минимальная выручка).
- **Доля мастера (master share)**: часть выручки, которая идёт сотруднику по итогам смены (процент или фикс).
- **Доля салона (salon share)**: часть выручки, которая остаётся бизнесу по итогам смены.
- **Доплата (topup)**: доплата до гарантированной суммы, если `master_share` меньше гарантии.

## Промо и акции

- **Промо / акция (promotion)**: маркетинговое предложение (скидка, бесплатная услуга и т.п.), действующее для определённых филиалов, услуг, периодов и условий.
- **Применение промо (promotion application)**: процесс применения акции к конкретной брони (учёт условий, ограничений по количеству, срокам и сумме).
- **Использование промо (promotion usage)**: запись о факте использования промо клиентом (`client_promotion_usage`).

## Пакеты визитов

- **Пакет визитов (visit package)**: проданный клиенту набор визитов по одному типу пакета: фиксированное количество посещений, срок действия и скидка. Учитывается в таблице `client_visit_packages`; при отметке посещения брони списывается один визит (приоритет над промо). См. [docs/SUBSCRIPTIONS_AND_PACKAGES_FEATURE.md](SUBSCRIPTIONS_AND_PACKAGES_FEATURE.md).
- **Тип пакета (visit package plan)**: шаблон пакета, который владелец создаёт в дашборде: название, число визитов, срок действия в днях, тип и значение скидки, привязка к услуге/филиалам. Хранится в `visit_package_plans`, используется при продаже пакета клиенту.
- **Остаток визитов (remaining visits)**: количество неиспользованных визитов по проданному пакету (`client_visit_packages.remaining_visits`). Уменьшается на 1 при отметке брони как «пришёл», если к брони применили этот пакет.

## Метрики, мониторинг и тесты

- **API‑метрики (api_request_metrics)**: таблица с логами запросов к API (endpoint, метод, статус, время, контекст), используемая для мониторинга и аналитики.
- **События воронки (funnel events)**: анонимизированные события воронки (просмотр бизнеса, выбор филиала/услуги/мастера, успешная бронь и т.п.) для продуктовой аналитики.
- **Core Web Vitals**: ключевые показатели качества фронтенда (LCP, FID/INP, CLS и др.), собираемые через web‑метрики.
- **Smoke‑тесты (smoke tests)**: базовый набор тестов, проверяющих, что ключевые экраны/сценарии запускаются без падений (используется для mobile и web).
- **E2E‑тесты (end‑to‑end)**: сквозные тесты пользовательских сценариев (публичное бронирование, работа смен, промо и др.) на основе Playwright.
