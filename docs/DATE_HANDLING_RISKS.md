# Известные риски дат и периодов

Статус: текущие наблюдения по исходникам, сверка 2026-11-01. Runtime/DB NOT_RUN. Основные правила — [модель дат](DATE_HANDLING_MODEL.md); продуктовые статусы остаются в [инженерном реестре](ENGINEERING_FINDINGS.md).

| Место | Что действительно делает код | Последствие / следующая проверка |
| --- | --- | --- |
| [Пакеты клиента](../apps/web/src/lib/meVisitPackagesHttpService.ts) | TODAY = new Date().toISOString().slice(0,10) вычислен один раз на уровне модуля | UTC-дата вместо явно выбранной бизнесовой, а после полуночи процесс может продолжить старую дату; проверить границу суток и срок пакета |
| [Cron смен](../apps/web/src/lib/closeShiftsCronService.ts) | Закрывает выбранные вчерашние смены, но buildMidnightNextDay получает now запуска | Граница закрытия строится от даты запуска, не от shift_date. Проверить closed_at и hours_worked независимо от текущей формулы |
| [Финансовая статистика](../apps/web/src/lib/staffFinanceStatsService.ts) | К month/year добавляется сегодняшняя открытая смена, даже если выбран прошлый период | dateFrom/dateTo ответа не гарантируют принадлежность всех строк; проверить исторический месяц/год с открытой текущей сменой |
| [Нормализация](../apps/web/src/lib/dateUtils.ts), [создание промо](../apps/web/src/lib/branchPromotionsService.ts), [обновление промо](../apps/web/src/lib/branchPromotionService.ts) | toNormalizedDateString берёт префикс YYYY-MM-DD, не переводит через UTC; невозможные календарные даты и обратный диапазон им не отсекаются | Старое описание toISOString в этих handlers устарело. Проверить полный входной контракт и ошибку до записи |
| [Общие time helpers](../apps/web/src/lib/time.ts) | Есть глобальный NEXT_PUBLIC_TZ/fallback и отдельный getBusinessTimezone; TZ фиксируется при загрузке | Наличие общего helper не доказывает, что каждый consumer передаёт зону бизнеса. Проверять выбранную цепочку, а не объявлять все даты унифицированными |

Согласованные подробности: [финансовые API](api/STAFF_AND_FINANCE.md), [пакеты и аналитика](api/BUSINESS_WORKFLOWS.md), [cron](../CRON_SETUP.md). Перечень — конкретные найденные риски, не доказательство отсутствия других date bugs.

Для новой правки записать исходный момент с timezone, календарный день бизнеса, ожидаемые границы периода и независимый ожидаемый результат. Пустая выборка или HTTP 200 не проверяют границу. Применённая удалённая SQL-версия и timezone среды в этой задаче не исследовались.
