# Исправление падающих тестов и ошибок lint — 10 ноября 2026

Статус: локальный инженерный отчёт. Аудитория: разработчик и ревьюер. Сопровождение: команда разработки. Это продолжение [пакета 9–10 ноября](../engineering-2026-11-09/summary.md); прежние результаты сохранены с датой наблюдения.

## Граница и причины

Прямой запрос человека разрешил сначала устранить причины семи падающих тестов и 52 ошибок web lint, сохранив проверки. Исходный HEAD — `b424cd396cbeefbe2a4173e0aa4583661e85ba87`; работа выполнена поверх уже изменённого дерева. Старую WEB-кампанию и automation не возобновляли. `.env`, удалённая БД, провайдеры, реальные сообщения и финансовые операции не использовались.

Семь падений из предыдущего полного прогона:

- Три проверки ProfileLoadFailureBoundary: ошибка чтения или отсутствие подтверждённого пользователя приводили к показу пустого редактируемого профиля. Теперь есть отдельные loading/ready/error состояния; retry открывает форму только после успешного чтения. Ошибка auth вместе с user также отклоняется.
- Три проверки RoleApplicationsReadState: ошибка запроса выглядела как достоверно пустой список. Теперь ошибка и повторная загрузка скрывают empty state, настройку филиала и действия по заявкам.
- StaffCabinetPages: SSR harness не предоставлял используемый компонентом App Router. Добавлена только имитация внешней навигации; реальный StaffBookingsView сохранён, поведение URL проверяется отдельными тестами.

Свежий исходный lint воспроизвёл **52 errors / 142 warnings**: 15 set-state-in-effect, 5 rules-of-hooks, 5 refs, 5 error-boundaries, 5 no-require-imports, 3 preserve-manual-memoization, 1 immutability и 13 no-console.

## Что исправлено

- Серверные страницы обрабатывают ошибки загрузки до построения JSX; ошибки дочернего рендера остаются в механизме React boundaries. CommonJS imports заменены статическими imports.
- Меню закрываются при смене маршрута; sidebar сохраняет смонтированный переключатель бизнеса, чтобы навигация не создавала лишний запрос. Список пользователей читает серверные rows/page/total напрямую, сохраняет фокус поискового поля и черновик при обновлении тех же фильтров.
- LanguageProvider и StaffOnboarding подписываются на внешние настройки через useSyncExternalStore. Проверены SSR/hydration, приоритет cookie → legacy storage → язык браузера, заблокированное хранилище, смена языка без потери черновика и межвкладочные события.
- Финансовый audit log изолирован по сотруднику; черновик расписания не сбрасывается при эквивалентном обновлении; услуги в ClientEditForm управляются родительским состоянием. Autosave получает callbacks и данные только завершённого render commit. Memo расчётов зависит от фактически используемых items/shift.
- Слоты и переносы принадлежат конкретному запросу. Смена параметров скрывает прежний результат, отменённый запрос не меняет текущие данные, возврат A → B → A повторно проходит проверку кэша. Ключ публичного кэша учитывает бизнес, филиал и расписание; сохранены debounce 300 ms, TTL 10 s и предел 100 entries. Очистка QuickDesk также инвалидирует ожидающий ответ.
- Hooks диагностик вызываются безусловно. useRenderCount возвращает getter числа завершённых commits; прежних рабочих callers не найдено. Логи используют shared sanitizer с сохранением уровней и production-политики legacy API; сведения об ограничениях обновлены в [справочнике логирования](../../../apps/web/src/lib/LOGGING_SECURITY.md).
- Toast отменяет оба таймера при замене/размонтировании и вызывает onClose однократно. Profile reminder снимает подписки и игнорирует поздние ответы после смены маршрута/авторизации.

Правила ESLint, Jest configuration, существующий coverage allowlist и порог 60% в этой итерации не ослаблялись. Старые семь проверок сохранены; добавлены регрессии загрузки, ошибок, гонок, hydration и lifecycle. В update-basic указан существующий структурный интерфейс Supabase boundary вместо чрезмерного разворачивания generic-типа; runtime-проверка прав не менялась.

## Оставшиеся границы

Это закрытие локальных gates, не готовность к production или большим нагрузкам. Release build, browser/provider/device E2E и применение миграций не выполнены. Штатный Playwright запускает приложение с локальной конфигурацией и включает зависимые от auth/fixtures сценарии; подтверждённого изолированного полного bootstrap для него пока нет. Старые окружения/роли не использовались.

В ENG-13 исправлена web-гонка, но single-service RPC по-прежнему получает слоты всего бизнеса, а клиенты фильтруют их; SQL-план и нагрузочный предел не измерены. Остаются обязательные rollout/миграционные условия предыдущего пакета, rate limiter, durable outbox, полнота больших выборок и CI — см. [инженерный реестр](../../ENGINEERING_FINDINGS.md).

При независимом review также отмечен прежний сценарий admin search: ответ на уже отправленный фильтр может заменить более новый поисковый черновик. Эта отдельная гонка не объявляется исправленной текущим сохранением фокуса/same-filter refresh.

Commit, stage, reset, push и deploy не выполнялись. Исторические WEB acceptance и paused automation не изменялись.
