## Границы

- SHA-256 подтверждает сохранность байтов, а не истинность наблюдения. Старые снимки экрана не объявляются заново просмотренными или device PASS.
- `contextualStageIds` означает только упоминание WB, не исходный retest. В verified засчитываются прямо названные исторические записи либо отдельное проверяемое уточнение.
- Before/after, локальные mock FAIL/PASS, служебные проверки и повторные summaries не суммируются как число проверенных сценариев.
- «Нет целевого свидетельства» не означает «никогда не тестировали». «Исторически open» не означает «свежевоспроизведён сейчас».
- Два Markdown final остаются в файловой описи; они не включены в 31 JSON summary. Ни один тип файла не потерян из 2 477.
- Первичные test-results остаются на исходных местах и могут быть ignored в Git. Без них на другой машине проверка должна честно сообщать missing, а не PASS. Архив не извлекает cookie/token и не обращается в сеть.
- Снимки документов отражают состояние на момент импорта; последующие ссылки/учётные правки активных документов не переписывают снимок. Полная приёмка текущего кандидата отдельно.

## Воспроизводимая проверка

`node scripts/web-verification-report.mjs --json` проверяет hashes, ссылки, знаменатель, дубликаты и допустимость исторических статусов. `node --test scripts/web-verification-report.test.mjs scripts/web-evidence-accounting.test.mjs` проверяет сам учёт, не приложение.

`scripts/web-evidence-audit.mjs` — read-only построитель новой описи; повторный запуск после изменений документов не является основанием перезаписать этот снимок. `scripts/web-evidence-migrate.mjs` только печатает полный patch реестра; сам ничего не записывает. Изменения принимаются явно через patch, затем проверяются. Генераторы сводок ничего не запускают в браузере, продукте или БД.
