## 1. Бэкапы и PITR в проде (самое важное)

**Решение владельца (24 ноября 2026):** пока это пет-проект, платный план и PITR откладываются до подготовки к публичному релизу. До тех пор — ручные снимки (шаг 5) перед крупными изменениями и миграциями.

Сейчас у проекта Supabase `beulnmftzbmtbdlgurht` нет ни ежедневных бэкапов, ни восстановления на момент времени (PITR). При ошибке или сбое данные клиентов, записей и финансов восстановить будет не из чего.

1. Откройте [supabase.com/dashboard](https://supabase.com/dashboard) → проект → **Project Settings → Billing**.
2. Ежедневные бэкапы есть только на платном плане (Pro и выше). Если проект на бесплатном плане — переведите его на Pro. Это платно: решение и оплата за вами.
3. PITR — отдельное платное дополнение: **Project Settings → Add-ons → Point in Time Recovery**. Хватит минимального периода (7 дней).
4. Проверьте, что бэкапы появились: **Database → Backups**. Там должен быть список дней (или окно PITR).
5. Пока платного плана нет, делайте ручной снимок перед крупными изменениями. Он хранится вне репозитория, в `C:\projects\kezek-backups\`, как и прежний: там персональные данные.

## 4. Новая сборка мобильного приложения (EAS)

Пока её нет, пользователи приложения не получат перевод на кыргызский и английский и исправления последних недель.

1. Желательно сначала сделать п. 2 и п. 3: значения EAS попадают в сборку только при её создании. Для push-уведомлений — сначала ключ FCM для Android ([подраздел ниже](#push-уведомления-в-приложении)).
2. В папке `apps/mobile` выполните вход, если ещё не вошли: `npx eas login`.
3. Сборка: `npx eas build --platform all --profile production` (номер версии растёт сам, `autoIncrement`).
4. Отправка в магазины: `npx eas submit --platform all --profile production`, затем в Google Play Console и App Store Connect выпустите версию.
5. Перед выпуском откройте пробную сборку (профиль `preview`) на телефоне и пройдите вход, запись и кабинет на кыргызском — это первый запуск перевода на устройстве.

## 5. E2E-тесты в CI — ничего делать не нужно

Задания `e2e_tests` и `e2e_visual_regressions` больше не используют секреты GitHub и не ходят на сайт: каждое поднимает в CI свой локальный Supabase, заполняет его тестовыми данными (`scripts/e2e-seed.mjs`) и запускает приложение рядом. ### Шаблоны WhatsApp для уведомлений о записи (R25-07)

Meta доставляет свободный текст только тому, кто сам написал бизнесу за последние 24 часа. Поэтому подтверждения, отмены и напоминания о записи уходят в WhatsApp только одобренными шаблонами. Без настроенного шаблона WhatsApp этого вида просто не планируется (не ошибка); для удержания слота (hold) шаблона нет.

1. [business.facebook.com](https://business.facebook.com) → **WhatsApp Manager → Message templates → Create template**. Категория **Utility**, тип **Default**. Имена ниже — предложение, можно свои.
2. Для каждого шаблона добавьте переводы: русский (`ru`) обязателен — он используется по умолчанию; кыргызский (`ky_KG`) и английский (`en`) — по желанию. Кыргызский текст ниже — черновик, покажите его носителю языка.
3. Порядок переменных одинаковый во всех трёх шаблонах и всех языках: `{{1}}` — бизнес, `{{2}}` — услуга, `{{3}}` — мастер, `{{4}}` — дата и время по часовому поясу бизнеса (например `01.12.2026 15:30`, на английском `1 Dec 2026, 15:30`), `{{5}}` — ссылка на запись (`https://kezek.vercel.app/booking/…`). Meta просит пример значения для каждой переменной — подставьте такие.
4. После одобрения задайте в Vercel (Production) и сделайте Redeploy:

| Переменная | Значение |
| --- | --- |
| `WHATSAPP_BOOKING_CONFIRMED_TEMPLATE_NAME` | имя шаблона «запись подтверждена», например `kezek_booking_confirmed` |
| `WHATSAPP_BOOKING_CANCELLED_TEMPLATE_NAME` | имя шаблона «запись отменена», например `kezek_booking_cancelled` |
| `WHATSAPP_BOOKING_REMINDER_TEMPLATE_NAME` | имя шаблона напоминания (за 24 ч и за 2 ч), например `kezek_booking_reminder` |
| `WHATSAPP_BOOKING_TEMPLATE_LANG` | код языка перевода по умолчанию; без значения — `ru` |
| `WHATSAPP_BOOKING_TEMPLATE_LANG_KY` | `ky_KG`, только когда кыргызский перевод одобрен во всех трёх шаблонах |
| `WHATSAPP_BOOKING_TEMPLATE_LANG_EN` | `en`, только когда английский перевод одобрен во всех трёх шаблонах |

Получатель с языком ky/en получает свой перевод, если задан его код, иначе — перевод по умолчанию (и значения переменных тоже на языке по умолчанию). Шаблон, имя которого задано, но не одобрено в Meta, приведёт к ошибке отправки, видимой в outbox.

### Push-уведомления в приложении

Приложение присылает клиенту push о подтверждении и отмене записи и напоминания за 24 и за 2 часа; мастеру со связанным аккаунтом — о подтверждении и отмене. Включается переключателем «Push-уведомления» в профиле приложения. Отправка идёт через Expo Push API тем же worker, что email и Telegram ([README уведомлений](../apps/web/src/lib/notifications/README.md#push-в-мобильном-приложении)). Push работает только в **новой сборке EAS** (п. 4): в установленных сейчас версиях модуля уведомлений нет.

1. **Миграция** `supabase/migrations/20261125170000_push_tokens.sql` в проде (таблица `push_tokens` и канал `push` очереди). Без неё регистрация токена отвечает 500, а подготовка уведомлений для клиента с токеном падает. Применять тем же порядком, что и остальные миграции.
2. **Android — ключ Firebase (FCM V1).** Без него Expo не доставит push на Android.
   1. [console.firebase.google.com](https://console.firebase.google.com) → создайте проект (или выберите существующий) → добавьте Android-приложение с package `kg.kezek.app`.
   2. Project settings → **Service accounts** → **Generate new private key** — скачается JSON-ключ сервисного аккаунта. Это секрет: не кладите его в репозиторий и не пересылайте.
   3. В папке `apps/mobile`: `npx eas credentials` → Android → production → **Push Notifications: FCM V1** (Manage your FCM V1 service account key) → загрузите скачанный JSON.
3. **iOS — ключ APNs.** Создаётся при сборке iOS: `npx eas build --platform ios` спросит, сгенерировать ли push-ключ, — ответьте «да» и войдите своим Apple ID (нужна Apple Developer Program). Отдельно в Apple ничего настраивать не нужно.
4. **Сборка и выпуск** — п. 4. На телефоне: войдите, откройте Профиль → включите «Push-уведомления» → разрешите уведомления. Сделайте тестовую запись, подтвердите её в кабинете бизнеса и дождитесь уведомления (worker запускается раз в 2 минуты и только при `BOOKING_NOTIFICATION_WORKER_ENABLED=true`). Нажатие на уведомление открывает запись.
5. **Необязательно:** если в проекте Expo (expo.dev → проект → Credentials) включена «Enhanced security for push notifications», создайте access token и добавьте его в Vercel как `EXPO_ACCESS_TOKEN`. Без этой настройки переменная не нужна.
