# Действия владельца

Статус: обновлено 28 ноября 2026. Здесь то, что код не может сделать сам: покупки, аккаунты, секреты, решения и сборки. Все значения вводит владелец; агенты их не видят и не вводят.

## Что мешает публичному запуску (обновлено 28 ноября 2026)

Кто: **владелец** — делаете вы сами (аккаунт, оплата, секрет); **агенты** — делает команда в коде; **решение владельца** — нужно ваше «да» или выбор, дальше делают агенты. Цены примерные, проверьте на сайте сервиса перед оплатой.

## Почта (R25-21)

Нужен свой домен (пункт 1): `kezek.vercel.app` для почты не подходит.

1. [resend.com](https://resend.com) → **Domains → Add domain** → введите поддомен для писем, например `mail.<ваш домен>`.
2. Resend покажет DNS-записи (SPF, DKIM). Добавьте их у регистратора домена и дождитесь статуса **Verified**.
3. В Vercel задайте `EMAIL_FROM` (например `Kezek <noreply@mail.<ваш домен>>`) и `ALERT_EMAIL_TO` — ваш адрес для алертов. Затем Redeploy.
4. Проверка: сделайте тестовую запись с email и дождитесь письма.

## Переменные окружения в Vercel

[vercel.com](https://vercel.com) → проект kezek → **Settings → Environment Variables**, окружение **Production**. После сохранения нужен **Redeploy** последнего деплоя: переменные подхватываются только при сборке и запуске.

| Переменная | Зачем | Значение |
| --- | --- | --- |
| `WHATSAPP_OTP_HASH_SECRET` | Без неё вход через WhatsApp в мобильном приложении отвечает 503 | Случайная строка 32+ символа, например из `openssl rand -hex 32`. Не меняйте её потом без нужды: старые коды перестанут сходиться |
| `WHATSAPP_APP_SECRET` | Без неё вебхук WhatsApp отвечает 503 | App Secret приложения Meta (**App settings → Basic**) |

| `EMAIL_FROM`, `ALERT_EMAIL_TO` | Письма и алерты | См. [Почта](#почта-r25-21) |
| Шаблоны WhatsApp о записи | Уведомления о записи в WhatsApp | После одобрения Meta, см. [таблицу ниже](#шаблоны-whatsapp-для-уведомлений-о-записи-r25-07) |

## Бэкапы и PITR в проде

**Решение владельца (24 ноября 2026):** пока это пет-проект, платный план и PITR откладываются до подготовки к публичному релизу. До тех пор — ручные снимки (шаг 5) перед крупными изменениями и миграциями.

Сейчас у проекта Supabase `beulnmftzbmtbdlgurht` нет ни ежедневных бэкапов, ни восстановления на момент времени (PITR). При ошибке или сбое данные клиентов, записей и финансов восстановить будет не из чего.

1. Откройте [supabase.com/dashboard](https://supabase.com/dashboard) → проект → **Project Settings → Billing**.
2. Ежедневные бэкапы есть только на платном плане (Pro и выше). Если проект на бесплатном плане — переведите его на Pro. Это платно: решение и оплата за вами.
3. PITR — отдельное платное дополнение: **Project Settings → Add-ons → Point in Time Recovery**. Хватит минимального периода (7 дней).
4. Проверьте, что бэкапы появились: **Database → Backups**. Там должен быть список дней (или окно PITR). Один раз восстановите бэкап в отдельный проект, чтобы убедиться, что это работает.
5. Пока платного плана нет, делайте ручной снимок перед крупными изменениями. Он хранится вне репозитория, в `C:\projects\kezek-backups\`, как и прежний: там персональные данные.

## Новая сборка мобильного приложения (EAS)

Пока её нет, пользователи приложения не получат перевод на кыргызский и английский и исправления последних недель. Бесплатные сборки Android на EAS закончились до **1 декабря 2026**.

1. Сначала сделайте то, что попадает в сборку только при её создании: [Sentry для приложения](#sentry-видеть-ошибки-в-проде), ключ FCM для Android ([push](#push-уведомления-в-приложении)), для iOS — аккаунт Apple и [вход через Apple](#вход-через-apple-r25-06).
2. В папке `apps/mobile` выполните вход, если ещё не вошли: `npx eas login`.
3. Сборка: `npx eas build --platform all --profile production` (номер версии растёт сам, `autoIncrement`). Без аккаунта Apple — только `--platform android`.
4. Отправка в магазины: `npx eas submit --platform all --profile production`, затем в Google Play Console и App Store Connect выпустите версию. Тексты и картинки для страниц в сторах готовят агенты.
5. Перед выпуском откройте пробную сборку (профиль `preview`) на телефоне и пройдите вход, запись и кабинет на кыргызском — это первый запуск перевода на устройстве.

### Вход через Apple (R25-06)

Код готов (28 ноября 2026): кнопка «Продолжить с Apple» есть только на iPhone, вход идёт через Supabase по нативному токену Apple, без браузера. Android и сайт не менялись. Без шагов ниже кнопка на iOS выдаст ошибку входа. Нужен аккаунт Apple Developer (примерно $99 в год).

1. **Apple Developer → Certificates, Identifiers & Profiles → Identifiers → `kg.kezek.app`**: включите **Sign in with Apple** («Enable as a primary App ID») и сохраните. EAS обычно включает это сам при сборке, но проверьте. Services ID и ключ .p8 для приложения не нужны: они нужны только для входа через Apple на сайте.
2. **Supabase → Authentication → Sign In / Providers → Apple**: включите провайдер. В **Client IDs** впишите `kg.kezek.app`. Поле Secret Key (for OAuth) оставьте пустым. Сохраните.
3. **Новая iOS-сборка** из `apps/mobile`: `npx eas build --platform ios --profile production`. Если EAS предложит обновить provisioning profile или capabilities — согласитесь. Обновление по воздуху (OTA) не поможет: нужен новый бинарник.
4. **Проверка на iPhone через TestFlight**: «Продолжить с Apple» → вход → приложение открывается под новым аккаунтом. При первом входе Apple передаёт имя: оно сохраняется в аккаунте и видно бизнесу в записи; поле имени в профиле, как и при входе через Google, клиент заполняет сам. Попробуйте и вариант «Скрыть e-mail».
5. *(Желательно, после R25-21)* Чтобы письма доходили на скрытые адреса `@privaterelay.appleid.com`: **Apple Developer → Services → Sign in with Apple for Email Communication** → добавьте домен, с которого Kezek отправляет письма. Вход работает и без этого.
6. В App Store Connect в заметках для ревью напишите: «Sign in with Apple is offered alongside Google on the sign-in screen».

### Публикация в сторах: что заполнить в консолях

Код к сторам проверен 28 ноября 2026: удаление аккаунта есть прямо в приложении, ссылки на политику и условия есть в профиле, `targetSdk` 36 подходит Google Play, ненужные разрешения убраны, ответ про шифрование (export compliance) задан в `app.json`. Осталось то, что делается только в консолях.

1. **Демо-аккаунты для проверяющих.** Проверяющие Apple и Google не получат код в WhatsApp или Telegram. Нужен вход, который они смогут пройти: Google-аккаунт или тестовые номера с постоянным кодом в Supabase (Authentication → Phone → test numbers). Лучше три роли: клиент, владелец, мастер. Данные впишите в App Store Connect (App Review Information) и в Play Console (App access). Агенты такие аккаунты не создают.
2. **`google-services.json` для push на Android.** Firebase → Project settings → ваше Android-приложение `kg.kezek.app` → скачайте файл. Без него push на Android не включится (ключа FCM в EAS для этого мало). Передайте файл агентам через EAS (`eas env:create` с типом file, имя `GOOGLE_SERVICES_JSON`) — агенты подключат его в `app.json`. Сам файл в репозиторий не кладите.
3. **Переменные EAS для профиля preview:** `EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`, `EXPO_PUBLIC_API_URL`. Без них пробная сборка закрывается при запуске (так задумано).
4. **Подпись.** Пусть EAS сам управляет ключами. Сохраните резервную копию ключа Android (`npx eas credentials` → Android → Download). SHA-256 ключа Play App Signing впишите в Vercel как `ANDROID_APP_LINK_SHA256_FINGERPRINTS` (MOB-05).
5. **App Store Connect:** App Privacy (черновик ответов — в аудите у агентов, ниже кратко), возрастной рейтинг (ожидается 4+), ссылки `https://kezek.vercel.app/privacy` и страница поддержки, демо-аккаунт. В `app.json` включены iPad (`supportsTablet`) — нужны скриншоты iPad 13", либо скажите агентам отключить iPad.
6. **Google Play Console:** Data safety (адрес удаления данных `https://kezek.vercel.app/data-deletion`), App access (демо-аккаунт), рейтинг IARC (ожидается Everyone), целевая аудитория 18+, реклама — «нет». Для `eas submit` нужен сервисный аккаунт Google (JSON-ключ храните в EAS, не в репозитории).
7. **Контактный email** для запросов о данных и удалении — его нет на страницах `/privacy` и `/data-deletion`, а Google Play его требует. Сообщите адрес, агенты добавят (R25-24).
8. **Тексты для сторов** готовы в [STORE_LISTINGS](marketing/STORE_LISTINGS.md) на трёх языках, со списком скриншотов. Кыргызскую часть нужно показать носителю языка.

Кратко для App Privacy / Data safety: приложение собирает имя, телефон, email (вход и записи), записи и отзывы (функции сервиса), примерное и точное местоположение только с разрешения — для поиска филиалов рядом и для точки филиала на карте у владельца, push-токен, данные о сбоях (Sentry, без IP). Ничего не передаётся для рекламы, отслеживания нет, данные передаются в бизнес, к которому вы записались. Шифрование при передаче — да. Удаление — да, в приложении.

## E2E-тесты в CI — ничего делать не нужно

Задания `e2e_tests` и `e2e_visual_regressions` больше не используют секреты GitHub и не ходят на сайт: каждое поднимает в CI свой локальный Supabase, заполняет его тестовыми данными (`scripts/e2e-seed.mjs`) и запускает приложение рядом. Если секреты `E2E_TEST_*` уже заведены, их можно удалить (Settings → Secrets and variables → Actions) — workflow их не читает. Подробности — в [справочнике Playwright](../apps/web/e2e/README.md).

### Шаблоны WhatsApp для уведомлений о записи (R25-07)

Meta доставляет свободный текст только тому, кто сам написал бизнесу за последние 24 часа. Поэтому подтверждения, отмены и напоминания о записи уходят в WhatsApp только одобренными шаблонами. Без настроенного шаблона WhatsApp этого вида просто не планируется (не ошибка); для удержания слота (hold) шаблона нет.

1. [business.facebook.com](https://business.facebook.com) → **WhatsApp Manager → Message templates → Create template**. Категория **Utility**, тип **Default**. Имена ниже — предложение, можно свои.
2. Для каждого шаблона добавьте переводы: русский (`ru`) обязателен — он используется по умолчанию; кыргызский (`ky_KG`) и английский (`en`) — по желанию. Кыргызский текст ниже — черновик, покажите его носителю языка.
3. Порядок переменных одинаковый во всех трёх шаблонах и всех языках: `{{1}}` — бизнес, `{{2}}` — услуга, `{{3}}` — мастер, `{{4}}` — дата и время по часовому поясу бизнеса (например `01.12.2026 15:30`, на английском `1 Dec 2026, 15:30`), `{{5}}` — ссылка на запись (`https://kezek.vercel.app/booking/…`). Meta просит пример значения для каждой переменной — подставьте такие.
4. После одобрения задайте в Vercel (Production) и сделайте Redeploy:

| Переменная | Значение |
| --- | --- |
| `WHATSAPP_BOOKING_CONFIRMED_TEMPLATE_NAME` | имя шаблона «запись подтверждена», например `kezek_booking_confirmed` |
| `WHATSAPP_BOOKING_CANCELLED_TEMPLATE_NAME` | имя шаблона «запись отменена», например `kezek_booking_cancelled` |
| `WHATSAPP_BOOKING_REMINDER_TEMPLATE_NAME` | имя шаблона напоминания (за 24 ч и за 2 ч), например `kezek_booking_reminder` |
| `WHATSAPP_BOOKING_TEMPLATE_LANG` | код языка перевода по умолчанию; без значения — `ru` |
| `WHATSAPP_BOOKING_TEMPLATE_LANG_KY` | `ky_KG`, только когда кыргызский перевод одобрен во всех трёх шаблонах |
| `WHATSAPP_BOOKING_TEMPLATE_LANG_EN` | `en`, только когда английский перевод одобрен во всех трёх шаблонах |

Получатель с языком ky/en получает свой перевод, если задан его код, иначе — перевод по умолчанию (и значения переменных тоже на языке по умолчанию). Шаблон, имя которого задано, но не одобрено в Meta, приведёт к ошибке отправки, видимой в outbox.

### Push-уведомления в приложении

Приложение присылает клиенту push о подтверждении и отмене записи и напоминания за 24 и за 2 часа; мастеру со связанным аккаунтом — о подтверждении и отмене. Включается переключателем «Push-уведомления» в профиле приложения. Отправка идёт через Expo Push API тем же worker, что email и Telegram ([README уведомлений](../apps/web/src/lib/notifications/README.md#push-в-мобильном-приложении)). Push работает только в **новой сборке EAS** ([сборка](#новая-сборка-мобильного-приложения-eas)): в установленных сейчас версиях модуля уведомлений нет.

1. ~~**Миграция** `supabase/migrations/20261125170000_push_tokens.sql` в проде.~~ Применена 25 ноября 2026 (таблица `push_tokens` и канал `push` очереди).
2. **Android — ключ Firebase (FCM V1).** Без него Expo не доставит push на Android.
   1. [console.firebase.google.com](https://console.firebase.google.com) → создайте проект (или выберите существующий) → добавьте Android-приложение с package `kg.kezek.app`.
   2. Project settings → **Service accounts** → **Generate new private key** — скачается JSON-ключ сервисного аккаунта. Это секрет: не кладите его в репозиторий и не пересылайте.
   3. В папке `apps/mobile`: `npx eas credentials` → Android → production → **Push Notifications: FCM V1** (Manage your FCM V1 service account key) → загрузите скачанный JSON.
3. **iOS — ключ APNs.** Создаётся при сборке iOS: `npx eas build --platform ios` спросит, сгенерировать ли push-ключ, — ответьте «да» и войдите своим Apple ID (нужна Apple Developer Program). Отдельно в Apple ничего настраивать не нужно.
4. **Сборка и выпуск** — [сборка EAS](#новая-сборка-мобильного-приложения-eas). На телефоне: войдите, откройте Профиль → включите «Push-уведомления» → разрешите уведомления. Сделайте тестовую запись, подтвердите её в кабинете бизнеса и дождитесь уведомления (worker запускается раз в 2 минуты и только при `BOOKING_NOTIFICATION_WORKER_ENABLED=true`). Нажатие на уведомление открывает запись.
5. **Необязательно:** если в проекте Expo (expo.dev → проект → Credentials) включена «Enhanced security for push notifications», создайте access token и добавьте его в Vercel как `EXPO_ACCESS_TOKEN`. Без этой настройки переменная не нужна.
