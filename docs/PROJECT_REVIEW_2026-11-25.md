# Ревью проекта 2026-11-25: серьёзные баги и что мешает считать проект готовым

Проверено шестью независимыми проходами по коду (бронирование, безопасность, деньги, мобильное приложение, уведомления и cron, готовность к релизу). Только чтение: прод не трогался. Каждая находка уровня «высокий» перепроверена по коду отдельно; у каждой указаны файл и сценарий. Уже закрытые пункты из [ENGINEERING_FINDINGS.md](ENGINEERING_FINDINGS.md) и [PROJECT_REVIEW_2026-11-17.md](PROJECT_REVIEW_2026-11-17.md) не повторяются.

Итог: двойных броней, утечек между бизнесами и повышения прав не найдено — ядро брони, смен и изоляции бизнесов устроено правильно. Мешают готовности три группы: ошибки в деньгах смены, мобильное приложение не пройдёт ревью сторов, и не закончены владельческие шаги после потери домена (почта, провайдеры входа, бэкапы, юридические тексты).

Статусы: OPEN — не исправлено; OWNER — нужен владелец; PRODUCT — нужно решение владельца о правиле.

## 4. Что проверено и работает правильно

Двойные брони исключены ограничением `no_overlap` и блокировкой строки мастера; истёкшие удержания освобождаются; слоты и удержание считают расписание одной функцией; границы дня и пояса бизнеса согласованы. Изоляция бизнесов: контекст менеджера и сотрудника перепроверяется, id-маршруты дашборда фильтруют по `biz_id`, админ-маршруты требуют супер-админа, cron и вебхуки проверяют секрет с постоянным временем сравнения. Деньги: двойное закрытие и правка после закрытия невозможны, одна бронь не попадает в две смены, абонемент и акция не списываются дважды, продажа абонемента идемпотентна, CSV совпадает с экраном. Mobile: прод-адрес API верный, вход по deep link принимает только PKCE-код, сессия в SecureStore, явный выход чистит всё, офлайн-очередь смены привязана к владельцу. Уведомления: письма идемпотентны, повторы ограничены, неопределённые отправки не повторяются, время в поясе бизнеса.
