# Сценарии тестирования переключения ролей

Чек-лист и ожидаемое поведение для проверки смены роли/кабинета: редиректы с `/`, заголовки, доступные действия. Связано с задачей в `OWNER_CABINET_RISKS_AND_IMPROVEMENTS_TASKS.md` (блок 5.9).

---

## 1. Редиректы с главной (`/`)

### 1.1. Один тип кабинета

| Роль пользователя | Ожидаемый редирект с `/` | Примечание |
|-------------------|--------------------------|------------|
| Только клиент (нет owner/staff/admin) | `/cabinet` | Мои записи |
| Только сотрудник (staff, нет manager roles) | `/staff` | Кабинет сотрудника |
| Только владелец/менеджер (один бизнес) | `/dashboard` | Кабинет бизнеса |
| Только владелец/менеджер (несколько бизнесов, нет `user_current_business`) | `/select-business` → затем `/dashboard` | Сначала выбор бизнеса |
| Только супер-админ | `/admin` | Админ-панель |

**Проверить:** авторизоваться под каждым типом, открыть `/` — должен быть один редирект в указанный кабинет (для нескольких бизнесов — цепочка select-business → dashboard).

### 1.2. Несколько типов кабинетов (без cookie предпочтения)

| Комбинация | Ожидаемый редирект с `/` |
|------------|---------------------------|
| Владелец + клиент (canDashboard, canCabinet) | `/select-cabinet` |
| Владелец + сотрудник (canDashboard, canStaff, canCabinet) | `/select-cabinet` |
| Сотрудник + клиент (canStaff, canCabinet) | `/select-cabinet` |
| Супер-админ + владелец (canAdmin, canDashboard, …) | `/select-cabinet` |

**Проверить:** пользователь с 2+ кабинетами, cookie `kezek_preferred_cabinet` удалена/не установлена → заход на `/` → редирект на `/select-cabinet`.

### 1.3. Несколько типов кабинетов (с cookie предпочтения)

Установить cookie `kezek_preferred_cabinet` = `cabinet` | `staff` | `dashboard` | `admin` (значение должно быть разрешено профилем).

| Cookie | Ожидаемый редирект с `/` |
|--------|---------------------------|
| `cabinet` | `/cabinet` |
| `staff` | `/staff` |
| `dashboard` | `/dashboard` (при нескольких бизнесах без current_biz — сначала `/select-business`) |
| `admin` | `/admin` (если canAdmin) |

**Проверить:** установить cookie, открыть `/` — редирект в выбранный кабинет. Если cookie невалидна (например `admin` у пользователя без canAdmin) — редирект на `/select-cabinet`.

## 2. Страница выбора кабинета (`/select-cabinet`)

- **Условие входа:** только при 2+ доступных кабинетах (middleware ведёт с `/` при отсутствии валидного предпочтения).
- **Элементы:** заголовок «Как вы хотите зайти?», подзаголовок, кнопки только для доступных кабинетов (Админ-панель, Кабинет бизнеса, Кабинет сотрудника, Мои записи), чекбокс «Запомнить выбор».
- **Действие:** клик по кнопке → при включённом «Запомнить» устанавливается cookie `kezek_preferred_cabinet` → переход по выбранному пути.
- **Проверить:** при одном кабинете заход напрямую на `/select-cabinet` → редирект на `/`. При неавторизованном → редирект на `/`.

---

## 3. Переключатель в шапке (RoleAndBusinessSwitcher)

- **Где:** в layout кабинета (dashboard/staff/cabinet) в шапке отображается текущая роль и при необходимости текущий бизнес.
- **Действия:** выбор пункта в дропдауне — переход в другой кабинет (`/dashboard`, `/staff`, `/cabinet`, `/admin`) или смена активного бизнеса (для дашборда).
- **Проверить:**
  - В дашборде в шапке виден текущий бизнес и дропдаун «Сменить бизнес» / переключение кабинетов.
  - В кабинете клиента (`/cabinet`) при наличии других ролей в дропдауне есть пункты «Кабинет бизнеса», «Кабинет сотрудника», «Админ-панель».
  - Клик по «Кабинет сотрудника» ведёт на `/staff`, по «Мои записи» — на `/cabinet`, по «Кабинет бизнеса» — на `/dashboard` (при нескольких бизнесах может понадобиться выбор бизнеса).
  - После смены бизнеса в дашборде контент (сотрудники, услуги и т.д.) соответствует выбранному бизнесу; заголовки страниц показывают название бизнеса.

---

## 4. Заголовки и контекст

- **Дашборд:** в сайдбаре/заголовках отображается название текущего бизнеса; после смены бизнеса через переключатель заголовки обновляются.
- **Кабинет сотрудника (`/staff`):** контекст сотрудника (смены, записи); нет путаницы с дашбордом.
- **Мои записи (`/cabinet`):** отображаются записи клиента; при наличии других ролей — баннер `CabinetOtherRolesBanner` со ссылками на другие кабинеты (если не скрыт).

**Проверить:** переключение роли/бизнеса через шапку не оставляет старый контекст в заголовках (актуальный бизнес/раздел).

---

## 5. Нет доступа к выбранному контексту

- **NO_BIZ_ACCESS** (потеря прав к текущему бизнесу): показывается экран с сообщением и ссылками «Мои записи», «Кабинет сотрудника» (и при наличии — «Кабинет бизнеса»). Не должно быть «тихого» переключения на другой бизнес без выбора пользователя.
- **Прямой заход на `/dashboard` без роли владельца/менеджера:** страница ошибки/нет доступа с явной ссылкой в кабинет сотрудника или «Мои записи».
- **Прямой заход на `/staff` без записи в staff:** сообщение и ссылки на другие кабинеты (ErrorDisplay, NO_STAFF_RECORD).

**Проверить:** отозвать у пользователя роль/бизнес или зайти под пользователем с одной ролью на URL другой роли — отображаются понятное сообщение и ссылки на доступные кабинеты.

## 6. UX-заметки (зафиксировать при прогоне)

- **Запоминание предпочтения:** cookie `kezek_preferred_cabinet` действует до года; при следующем заходе на `/` пользователь сразу попадает в выбранный кабинет. Если права на этот кабинет отозваны — middleware ведёт на `/select-cabinet` (предпочтение невалидно).
- **Выбор бизнеса после «Кабинет бизнеса»:** при нескольких бизнесах и отсутствии `user_current_business` после перехода в `/dashboard` срабатывает редирект на `/select-business`; после выбора бизнеса — снова `/dashboard`.
- **Мобильная версия:** переключатель в шапке и кнопки на `/select-cabinet` должны оставаться удобными (размер, кликабельность).
- **Терминология:** везде единые названия: Кабинет бизнеса, Кабинет сотрудника, Мои записи, Админ-панель (см. CABINET_TERMINOLOGY_AUDIT.md).
