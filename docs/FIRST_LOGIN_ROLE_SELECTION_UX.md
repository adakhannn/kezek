# UX выбора кабинета при первом входе (несколько ролей)

Дизайн экрана/диалога «Как вы хотите зайти: владелец / сотрудник / клиент» при первом входе пользователя с несколькими ролями. Связано с задачей в `OWNER_CABINET_RISKS_AND_IMPROVEMENTS_TASKS.md` (блок 5.9) и с `docs/MULTI_ROLE_UX_SCENARIOS.md` (раздел 4.2).

---

## 1. Цель

- Убрать ощущение «меня всегда кидает не туда» у пользователей с несколькими ролями (владелец+клиент, владелец+сотрудник, супер-админ+владелец и т.д.).
- Дать явный выбор кабинета при заходе на главную (`/`), вместо автоматического редиректа по приоритету (admin → dashboard → staff → cabinet).
- Сохранять выбор пользователя (опционально), чтобы при следующих заходах сразу вести в выбранный кабинет.

---

## 2. Условие показа экрана выбора

Экран показывать **только если у пользователя доступно более одного типа кабинета**:

| Типы кабинетов | Условие из профиля |
|----------------|--------------------|
| Кабинет бизнеса | `profile.canDashboard` |
| Кабинет сотрудника | `profile.canStaff` |
| Мои записи (клиент) | `profile.canCabinet` (всегда true для авторизованных) |
| Админ-панель | `profile.canAdmin` |

**Показать экран выбора**, если выполнено одно из:

- `canAdmin` + хотя бы один из `canDashboard`, `canStaff`, `canCabinet`;
- `canDashboard` + хотя бы один из `canStaff`, `canCabinet`;
- `canStaff` + `canCabinet`.

Иначе (одна роль) — текущее поведение: редирект с `/` сразу в единственный доступный кабинет по приоритету.

---

## 3. Варианты реализации

### Вариант A: Отдельная страница `/select-cabinet` (рекомендуется)

- При заходе на `/` и наличии нескольких кабинетов middleware редиректит на `/select-cabinet`.
- Страница рендерит заголовок и кнопки/карточки только для доступных кабинетов (данные профиля — с сервера или через API).
- После выбора: запись предпочтения (cookie или localStorage) → редирект в выбранный кабинет. Для «Кабинет бизнеса» при нескольких бизнесах и отсутствии `user_current_business` после редиректа в `/dashboard` уже сработает переход на `/select-business` (текущая логика).

**Плюсы:** явный шаг, единое место для выбора, легко добавить «Запомнить выбор».  
**Минусы:** один дополнительный переход.

### Вариант B: Модальное окно на целевой странице

- Middleware по-прежнему редиректит по приоритету (например, в `/dashboard`).
- Layout целевой страницы (dashboard/staff/cabinet) при первом визите в сессии и при нескольких ролях показывает модал «Выберите кабинет» с кнопками перехода в другие кабинеты; можно добавить «Запомнить и больше не показывать».

**Плюсы:** не меняем цепочку редиректов.  
**Минусы:** краткое отображение «не того» кабинета до закрытия модала; логика «первый визит» сложнее (cookie/session).

### Вариант C: Выбор только при отсутствии сохранённого предпочтения

- Как вариант A, но на `/select-cabinet` попадают только пользователи без сохранённого выбора (cookie `kezek_preferred_cabinet`). Если предпочтение есть, middleware с `/` сразу редиректит в соответствующий кабинет (dashboard/staff/cabinet/admin).
- На странице выбора — кнопка «Запомнить мой выбор»; при выборе кабинета с этой галочкой записываем cookie (или localStorage + API), при следующих заходах редирект сразу в выбранный кабинет.

Рекомендация: **Вариант A** (отдельная страница), с опциональным запоминанием по Варианту C.

---

## 4. Элементы экрана (страница `/select-cabinet`)

### 4.1. Заголовок и текст

- Заголовок: **«Как вы хотите зайти?»** / **«Выберите кабинет»** (i18n: `selectCabinet.title`).
- Подзаголовок (опционально): «У вас есть доступ к нескольким кабинетам» (i18n: `selectCabinet.subtitle`).

### 4.2. Блоки выбора

По одному блоку на каждый **доступный** тип кабинета (по данным профиля):

| Кабинет | Условие | Путь | Текст кнопки/карточки (i18n) |
|---------|----------|------|------------------------------|
| Админ-панель | `profile.canAdmin` | `/admin` | `selectCabinet.optionAdmin` |
| Кабинет бизнеса | `profile.canDashboard` | `/dashboard` (далее при необходимости `/select-business`) | `selectCabinet.optionDashboard` |
| Кабинет сотрудника | `profile.canStaff` | `/staff` | `selectCabinet.optionStaff` |
| Мои записи | `profile.canCabinet` | `/cabinet` | `selectCabinet.optionCabinet` |

Отображать только те блоки, для которых условие истинно. Клик по блоку → сохранение выбора (если включено «Запомнить») → переход по указанному пути.

### 4.3. Запоминание выбора

- Чекбокс или переключатель: **«Запомнить выбор и в следующий раз заходить сюда»** (i18n: `selectCabinet.rememberChoice`).
- При включённом «Запомнить» и выборе кабинета сохраняем предпочтение (см. раздел 5). При следующих заходах на `/` middleware или клиентский редирект отправляет сразу в этот кабинет, без показа `/select-cabinet`.

### 4.4. Визуал

- Карточки или крупные кнопки с иконкой и текстом; текущая терминология из `CABINET_TERMINOLOGY_AUDIT.md`: «Кабинет бизнеса», «Кабинет сотрудника», «Мои записи», «Админ-панель».
- Адаптивная вёрстка под мобильные устройства.

---

## 5. Хранение предпочтения и логика редиректа

### 5.1. Где хранить

- **Вариант 1 (cookie):** cookie `kezek_preferred_cabinet` со значением `admin` | `dashboard` | `staff` | `cabinet`. Middleware может читать cookie и при заходе на `/` редиректить сразу в соответствующий путь (для `dashboard` затем сработает существующая логика `/select-business` при необходимости).
- **Вариант 2 (localStorage):** ключ `kezek_preferred_cabinet`. Middleware не видит localStorage; тогда при нескольких ролях всегда редирект на `/select-cabinet`, а уже клиентская страница при наличии значения в localStorage сразу редиректит в нужный кабинет (без показа кнопок). Либо ввести API `GET /api/me/preferred-cabinet` и `POST /api/me/preferred-cabinet`, хранить в БД и отдавать в middleware через cookie после установки.

Рекомендация для первого этапа: **cookie** (проще для middleware и не требует новых API).

### 5.2. Поведение middleware при pathname === '/'

Предлагаемая последовательность (после внедрения):

1. Получить профиль (`getUserRoleProfile`).
2. Если профиля нет — не менять редирект (или оставить текущее поведение для неавторизованных).
3. Если у пользователя **один** доступный тип кабинета — редирект по текущему приоритету (admin → dashboard → staff → cabinet), с учётом `select-business` для dashboard при нескольких бизнесах.
4. Если у пользователя **несколько** типов кабинетов:
   - если есть cookie `kezek_preferred_cabinet` с допустимым значением и этот кабинет доступен по профилю — редирект в соответствующий путь;
   - иначе — редирект на `/select-cabinet`.
5. На `/select-cabinet` при выборе кабинета с «Запомнить» — установка cookie (path=/, maxAge по желанию, например 1 год).

### 5.3. Вспомогательная функция

В `authContext.ts` (или отдельном модуле) можно ввести:

- `countAvailableCabinetTypes(profile: UserRoleProfile): number` — считает, сколько из `canAdmin`, `canDashboard`, `canStaff`, `canCabinet` истинно (при этом `canCabinet` всегда true для авторизованных, но для «одна роль» можно считать только «привилегированные» кабинеты).
- Уточнение: «несколько ролей» = два и более из: admin, dashboard, staff, cabinet. Тогда для «только клиент» count = 1 (cabinet), экран не показываем.

---

## 6. Интеграция с текущим потоком

- **Супер-админ с одной ролью (только admin):** экран не показываем, редирект в `/admin`.
- **Владелец + клиент (dashboard + cabinet):** показываем экран; при выборе «Кабинет бизнеса» → редирект в `/dashboard`; при нескольких бизнесах и отсутствии `user_current_business` уже существующий механизм отправит на `/select-business`.
- **Владелец + сотрудник (dashboard + staff + cabinet):** на экране три опции (Кабинет бизнеса, Кабинет сотрудника, Мои записи).
- **Только сотрудник:** один тип кабинета (staff + cabinet; если считать «клиент» отдельно, то два — тогда показываем экран с «Кабинет сотрудника» и «Мои записи»). При желании можно не показывать экран, если доступны только staff и cabinet (оставить приоритет staff). Это уточняется при реализации.

Рекомендация: считать «несколько типов» при count ≥ 2; для «только staff» и «только cabinet» (оба true) — показывать экран с двумя кнопками.

---

## 7. Сводка решений

| Вопрос | Решение |
|--------|---------|
| Когда показывать | При заходе на `/` и наличии у пользователя ≥2 типов кабинетов (по профилю). |
| Где реализовать | Отдельная страница `/select-cabinet` (Вариант A). |
| Запоминание | Опция «Запомнить выбор»; значение в cookie `kezek_preferred_cabinet`. |
| Редирект с `/` | При нескольких ролях: если есть валидный cookie — редирект в выбранный кабинет; иначе — редирект на `/select-cabinet`. |
| Терминология | Единая с проектом: Кабинет бизнеса, Кабинет сотрудника, Мои записи, Админ-панель (i18n). |
| Данные профиля | Использовать существующий `UserRoleProfile` (`getUserRoleProfile`); страница получает профиль с сервера (RSC) или через API. |
