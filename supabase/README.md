# Supabase: схема и подготовка окружения

Статус: действующий справочник репозитория. Обновлено 30 октября 2026. Ответственная роль: сопровождающий БД; конкретный исполнитель операций назначается в отдельной задаче.

Первый запуск приложения описан в [GETTING_STARTED.md](../GETTING_STARTED.md), эксплуатационные зависимости — в [OPERATIONS.md](../docs/OPERATIONS.md).

## Что хранится здесь

| Путь | Назначение и ограничение |
| --- | --- |
| [config.toml](config.toml) | Конфигурация локального Supabase; не подтверждает настройки удалённого сервера |
| [migrations/](migrations/) | Версионированные определения и изменения схемы; наличие файла не доказывает его применение |
| [seed.sql](seed.sql) | Данные и инициализация для локального стенда после миграций; требует уже созданную схему |
| [APPLY_MIGRATIONS.md](APPLY_MIGRATIONS.md) | Условия подготовки, применения и сверки миграций |
| [BACKUP_AND_RESTORE.md](BACKUP_AND_RESTORE.md) | Требования к резервным копиям и доказательству восстановления |
| [FIX_BEFORE_MIGRATION.md](FIX_BEFORE_MIGRATION.md) | Историческая справка об изменении `hours_worked`; не инструкция к повторному запуску |

Отдельные `fix_*.sql`, `debug_*.sql` и диагностические SQL в корне этой папки не образуют штатную очередь применения. Сначала требуется установить их назначение, актуальность и последствия для выбранного окружения.

## Известный пробел: нет полного baseline

Пустую БД нельзя воспроизвести только из текущей цепочки миграций:

- [20250102000000](migrations/20250102000000_update_booking_status_without_check.sql) использует уже существующий тип `booking_status`;
- [20250103000000](migrations/20250103000000_add_staff_avatar_url.sql) изменяет `staff`;
- [20250104000000](migrations/20250104000000_add_client_email_to_bookings.sql) изменяет `bookings`;
- создание исходных `businesses`, `bookings`, `staff`, `services`, `roles` и `booking_status` в SQL-цепочке не найдено; дополнительный `schema_paths` в конфигурации пуст.

Это вывод из исходников, а не результат запуска reset. Команда `supabase db reset` запускает миграции и seed, но отсутствующие определения не восстанавливает. До отдельной задачи по baseline для разработки требуется подготовленное dev-окружение с подтверждённым доступом либо проверенный внешний baseline. Сам внешний baseline в этом репозитории не предоставлен.

Для кампании действуют ограничения [WEB_AGENT_HANDOFF.md](../docs/WEB_AGENT_HANDOFF.md), включая доступ к Supabase только через обычный UI. Кампания закрыта, `kezek` — PAUSED.

Редактура документов 30 октября не запускает серверы, миграции, seed, reset, backup или restore. В этой задаче запрещён и удалённый reset. Для будущей операции нужны явно определённые цель и доступ; источник истины о применённых миграциях — состояние выбранной БД и его проверенные evidence, не имя SQL-файла.

## Подготовка будущей задачи по БД

1. Установить точное dev/staging/production-окружение и разрешённый способ доступа; не выводить ключи или connection strings в отчёт.
2. Определить происхождение базовой схемы, версию PostgreSQL и установленную историю миграций. Локальный [config.toml](config.toml) задаёт PostgreSQL 17; версия удалённого проекта здесь не проверена.
3. Сопоставить схему, функции, grants/RLS и исходники по [порядку миграций](APPLY_MIGRATIONS.md).
4. Для нового стенда сначала закрыть пробел baseline и подтвердить воспроизводимое восстановление в изоляции.
5. Назначить проверки результата и условия остановки до изменения данных.

Docker требуется для локального Supabase. Пакет CLI объявлен в корневом [package.json](../package.json); используйте согласованную с lockfile версию, а не произвольный `@latest` из старой инструкции.

## Типы приложения

Снимок типов находится в [apps/web/src/types/supabase.ts](../apps/web/src/types/supabase.ts). Его наличие не подтверждает автоматическую синхронизацию с удалённой схемой. Генерация типов — отдельное действие над явно выбранной БД; перед заменой файла требуется проверить источник, diff и совместимость потребителей. Общие имена переменных подключения перечислены в [ENV_GUIDE.md](../ENV_GUIDE.md); значения секретов в документацию не включаются.
