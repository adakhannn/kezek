# Настройка среды Kezek

Статус: действующий справочник по настройке; проверен по исходникам 30 октября 2026. Ответственная роль: сопровождающий среды разработки. Успешный запуск на новой машине этой редакцией не подтверждён.

Это основной документ установки и первого запуска. [Онбординг](docs/ONBOARDING.md) содержит короткий маршрут, [индекс документации](docs/README.md) — остальные источники.

## Перед началом

Прочитайте [CONTRIBUTING.md](CONTRIBUTING.md) и [текущий статус проекта](docs/PROJECT_STATUS.md). Команды ниже предназначены для задачи, в которую входит запуск приложения. Ограничения закрытой WEB-кампании находятся в [handoff](docs/WEB_AGENT_HANDOFF.md); документационная задача её не возобновляет.

Сначала установите, какое окружение разрешено для задачи, кто предоставляет доступ и какие данные в нём допустимо использовать. Локальный Next.js может обращаться к удалённой БД и реальным интеграциям; адрес `localhost` сам по себе не делает работу изолированной.

## Требования и установка

- Node.js **20.19.4 или выше в совместимой ветке**: в [корневом lockfile](pnpm-lock.yaml) Next.js 16 требует минимум 20.9.0, React Native 0.81.5 — 20.19.4. [CI](.github/workflows/ci.yml) использует ветку Node.js 20; другие ветки этим документом не проверены.
- pnpm **10.28.0**, как указано в `packageManager` корневого [package.json](package.json).
- Docker нужен для локального Supabase. Наличие Docker не устраняет отсутствующий baseline схемы, описанный ниже.

В уже полученном checkout установка выполняется из корня монорепозитория:

```bash
pnpm install --frozen-lockfile
```

Рабочие пакеты: `apps/web`, `apps/mobile`, `packages/core-domain`, `packages/shared-client`. Не заменяйте lockfile и не переустанавливайте зависимости отдельно в приложениях для обхода ошибки установки; сначала разберите несовпадение manifest/lockfile.

## База данных: обязательная зависимость

**Репозиторий пока не содержит полного bootstrap пустой БД.** Ранние миграции используют существующие `booking_status`, `staff` и `bookings`, а определения исходных таблиц и enum в цепочке отсутствуют. В [config.toml](supabase/config.toml) нет дополнительного `schema_paths`; [seed.sql](supabase/seed.sql) вставляет данные после миграций и не создаёт базовую схему.

Поэтому `supabase db reset` нельзя считать рабочей инструкцией восстановления проекта с нуля. Для полноценного запуска нужен один из вариантов:

- ранее подготовленное dev-окружение, доступ к которому явно предоставлен для текущей задачи;
- проверенный baseline схемы и согласованный порядок последующих миграций для нового изолированного окружения.

Второй вариант ещё требует отдельной инженерной работы и подтверждения восстановления. Наличие SQL-файла не доказывает его применение на удалённом сервере. Подробности: [Supabase](supabase/README.md), [миграции](supabase/APPLY_MIGRATIONS.md), [восстановление](supabase/BACKUP_AND_RESTORE.md).

## Переменные окружения

Частичный справочник имён и интеграций: [ENV_GUIDE.md](ENV_GUIDE.md). Шаблоны находятся в `apps/web/.env.example` и `apps/mobile/.env.example`. Создавайте локальный файл только при его отсутствии; не перезаписывайте существующие значения. Секреты передаются через предусмотренный для команды защищённый канал, не через документацию, issue или логи.

### Web

Файл: `apps/web/.env.local`.

| Имя | Назначение |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | URL согласованного dev-проекта |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Публичный ключ этого же проекта |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ для привилегированных обработчиков; не размещать в клиентских переменных |
| `NEXT_PUBLIC_SITE_ORIGIN` | Origin приложения, например `http://localhost:3000` |
| `RESEND_API_KEY`, `EMAIL_FROM` | Email-интеграция; нужны при разрешённой проверке соответствующих функций |

Отсутствие ключей уведомлений означает недоступность соответствующих функций, а не подтверждённый режим без отправки. Подключение реальных email/SMS/ботов требует разрешённого сценария и получателей. Имена дополнительных настроек Redis, cron, Sentry, OAuth и карт описаны в [ENV_GUIDE.md](ENV_GUIDE.md) и профильных документах.

### Mobile

Файл: `apps/mobile/.env.local`.

- `EXPO_PUBLIC_SUPABASE_URL`
- `EXPO_PUBLIC_SUPABASE_ANON_KEY`
- `EXPO_PUBLIC_API_URL` — адрес разрешённого web API, доступный устройству/эмулятору.

Не подставляйте production URL как значение по умолчанию для разработки. `localhost` на телефоне указывает на сам телефон; адрес dev-сервера или tunnel выбирается для конкретного стенда. Серверные секреты нельзя помещать в `EXPO_PUBLIC_*`.

## Первый запуск для разрешённой задачи

После подготовки БД, зависимостей и конфигурации:

```bash
pnpm -C apps/web dev
```

Web использует `http://localhost:3000` по умолчанию. При работе в существующей сессии сначала проверьте актуальное состояние сервера; не создавайте второй процесс и не перезапускайте неизвестный процесс по старому PID из отчёта.

Для отдельной задачи mobile:

```bash
pnpm -C apps/mobile start
```

Сведения об эмуляторах и нативных сборках: [mobile README](apps/mobile/README.md). Ограничения старого WEB-прогона не устанавливают WEB-only scope для новой явно запрошенной mobile-задачи.

Наличие страницы или успешный старт сервера не подтверждает корректность auth, RPC, RLS, финансов или фоновых задач. Проверки выбираются под конкретное изменение по [CONTRIBUTING.md](CONTRIBUTING.md) и [TESTING_GUIDE.md](TESTING_GUIDE.md). Эти документы не разрешают запуск запрещённого E2E runner в рамках прежнего WEB workflow.

## Если запуск не удался

| Симптом | Что проверить |
| --- | --- |
| Отсутствует переменная Supabase | Путь файла приложения и наличие нужных имён; не печатать значения ключей |
| Нет таблицы, enum или RPC | Соответствие подготовленной схемы исходникам; не выполнять произвольный `db push` или reset |
| Auth или публичный каталог недоступны | Точное окружение, код ошибки и доступность нужной поверхности; не считать старые наблюдения актуальным health-check |
| Ошибка установки | Версии Node/pnpm и соответствие lockfile; не обновлять зависимости вслепую |
| Не проходят тесты | Сопоставить конкретные ошибки с [текущим статусом](docs/PROJECT_STATUS.md); не снижать порог покрытия ради зелёного результата |

Эксплуатационные зависимости и подтверждения готовности ведутся отдельно в [OPERATIONS.md](docs/OPERATIONS.md).
